# AE-2772 Restructure A0 energy efficiency class into a selection of additional A0 markings

## AE-2772 Muutetaan A0 energialuokka monitilaiseksi A0 lisämerkinnäksi

(Original ticket text, as defined in collaboration with customer)

Varsinaisiksi energialuokiksi jäävät A+ ja aiemmat luokat A-G

Nykyinen ET2027 “täyttää A0 vaatimukset” -checkbox korvataan
monivalinnalla “Täyttää päästöttömän rakennuksen vaatimukset”
vaihtoehdoilla

- Ei, Rakennus ei täytä päästöttömälle rakennukselle asetettuja
  vaatimuksia
- A0, Rakennus täyttää uuden päästöttömän rakennuksen vaatimukset
  (ns. perusmuotoinen A0)
- A0_korjattu, Rakennus täyttää korjatun päästöttömän rakennuksen
  vaatimukset
- A0_MPR, Rakennus täyttää uuden päästöttömän massiivipuurakennuksen
  vaatimukset

Tämän asian puitteissa **ei muuteta PPP toimintaa**.

Merkintävaihtoehtoihin liittyy joukko vaatimuksia,
**joiden toteutumista ETP ei tarkista**, vaan tämä on laatijan
vastuulla ja tarvittaessa korjataan valvonnassa.

Odotettuja seurauksia:

- A0 ei saa energialuokan nuolikuvioon omaa värillistä nuolta
  - nuolikuvion väriskaala ja nuolien pituudet muuttuvat

- A0 ei näy julkisen tilastosivun E-luokkien jakauman pylväsdiagrammissa
  - Tilastoon ei tehdä tässä vaiheessa erikseen näkyvyyttä
    A0-luokille. Odotetaan, että sellaiset tullaan määrittelemään ja
    toteuttamaan myöhemmin.

- PPP ei sisällä pyöreänurkkaista värinuolta erikseen A0 -luokalle

Muita oletuksia:

- A+ -luokka vaatii **perusmuotoisen** tai **A0_MPR** -tyyppisen
  A0-merkinnän ja A+ -luokan erillisen “täyttää vaatimukset”
  -merkinnän
- A0 -luokan vaatimusten täyttyminen (kyllä/ei) merkitään erikseen
  ET:lle ja PPP suunniteltujen parannusten lopputilanteelle
  - mutta ei kuitenkaan jokaiselle PPP vaiheelle (epävarma, Ulla
    kysynyt ja odottaa vastausta)

## Notes from refinement


### Class calculation (A0 thresholds)

- A0 is no longer an energy class, so the A0 e-luku thresholds are removed
  from the 2027 raja-asteikko. The classes are A+, A, B, C, D, E, F, G.
- The A0 markings (A0, A0_korjattu, A0_MPR) have no e-luku threshold
  enforced by ETP. Possible future e-luku requirements for the markings
  are not enforced by ETP, as with the other marking requirements.
- A building whose e-luku falls in the former A0 range gets the class
  given by the remaining thresholds (A), regardless of the A0 marking.

### Existing data

- No ET2027 certificates exist in production, so no data migration of
  existing A0 e-luokka / `tayttaa-a0-vaatimukset` values is required.
- Test environments contain ET2027 certificates with A0. How their
  e-luokka appears after the change is not important
- Schema changes (and audit tables) can therefore replace the boolean
  without backwards-compatible data conversion.

### A+ class eligibility

- A+ requires an A0 marking of either A0 (basic) or A0_MPR, plus the
  separate A+ "täyttää vaatimukset" flag, plus an A+-eligible e-luku.
- A0_korjattu and "Ei" never lead to A+.
- If the A+ flag is set but the marking is not eligible (A0_korjattu or
  "Ei"), the certificate is not blocked by validation; the e-luokka
  simply resolves to A, as with the existing downgrade behaviour.
- The same rule must hold in both the backend (`downgrade-e-luokka`) and
  its frontend counterpart (`applyEluokkaDowngrade`).

### PPP (perusparannuspassi)

- The PPP `passin-perustiedot` `tayttaa-a0-vaatimukset` boolean is
  replaced by the same four-state marking as in ET2027, so that PPP
  phases keep sharing the e-luokka calculation with ET2027.
- "PPP functionality is not changed" is interpreted as: no new PPP
  features or flows. The field type change (schema, DB, form, PDF) and
  the removal of A0 as a class in PPP calculations are in scope.
- Today the PPP flag is one value in `passin-perustiedot` applied to all
  vaiheet (not per phase), and the lähtötilanne uses the ET's own flag.
  There is no information indicating a per-phase marking is needed, so
  the implementation assumes the marking is per PPP (one value for the
  whole passport), as today.

### PDF rendering and graphics

- No design spec exists yet for the new arrow chart; an updated reference
  document is expected later. Most PDF changes are out of scope for this
  ticket, and the current layout is kept as close as practical.
- Changes are made only where there is a practical reason, e.g. the
  stacked-arrow diagram can no longer have an A0 arrow because A0 is not
  a class. As a placeholder, the colouring of the affected arrow(s) is
  changed to gray (or similar) to make it evident that the diagram needs
  a design revision.
- Printing of the chosen A0 marking on the ET/PPP PDFs, new wording and
  Swedish texts are deferred to the follow-up work based on the
  reference document, except where needed to keep PDFs generating
  without errors (e.g. no references to the removed boolean or class).

### Search and CSV export

- A0 is removed from the e-luokka options in the search inputs (and the
  related frontend tests/expectations).
- Making the new A0 marking searchable is out of scope.
- The CSV export carries the new four-state marking in place of the old
  `tayttaa-a0-vaatimukset` flag (for both ET and PPP columns where the
  flag is currently exported).

### API compatibility and naming

- The ET2027 API is not yet stable, so the old `tayttaa-a0-vaatimukset`
  field can be removed and replaced by the new field without a
  compatibility layer.
- Naming of the new field, its values (API/DB representation of A0,
  A0_korjattu, A0_MPR, "Ei") and the DB representation are decided at
  implementation time.

### Texts and translations

- Finnish labels for the four options are taken from the ticket text.
- Proper Swedish translations are out of scope; they are done in the
  larger planned translation effort. New Swedish texts follow the
  existing placeholder convention: the Finnish text with an " (sv)"
  suffix (as in `localization.clj`, e.g. "Lähtötilanne (sv)").
